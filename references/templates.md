# AGENTS.md 文档模板

四种篇型的骨架。`<>` 为占位;**词汇按形态替换**(见文末映射表)。所有链接用相对路径。

## 词汇映射(形态 → 模板用语)

| 形态 | 树的中间层叫 | 叶子单元叫 | 入口文件 |
|---|---|---|---|
| Rust workspace | 层 | crate | `src/lib.rs` |
| JS monorepo | 组(或按包域) | package | `src/index.ts` |
| Python(src 布局) | 域 | subpackage | `__init__.py` |
| Go(multi-module) | 组 | module / package | `doc.go` / 包目录 |

模板中以 `<单元>` / `<组>` 行文,生成时换成左列对应词。

## 通用规则(所有篇型)

1. **顶部必有 `> **何时读我**：<可操作触发条件>`**(根篇除外——根篇常驻上下文,不写此句)。条件须回答"改什么/排查什么时来读我",禁止"想了解本目录时读我"这类同义反复。
2. 一个事实只在一处详述,别处用链接 + 一句定性引用("细则见 X 篇,本篇不重复")。
3. 契约条目用**加粗断言句**写,含"是什么 + 在哪 + 破坏了会怎样",不写空话。
4. 行数预算见 SKILL.md 速查表;超预算即触发 splitting.md 的下拆判断。
5. 语言跟随目标项目;命令必须实际可跑。

## 开发流程检查表(改任何代码前必读)

**新功能**或 **bug 修复**提交前,必须逐条走完:

1. <测试/用例同步规则,含落点目录与断言口径>
2. <公开面变更时的下游文档同步规则>
3. <覆盖矩阵同步>
4. **AGENTS.md 分层索引同步** —— 修改或新增代码时,对应 AGENTS.md(该 <单元> 篇、其所在组篇、根导航表)必须同步更新;契约/同步点/禁止事项变化即改对应篇,导航目标增删即改根表。按下表定位:

   | 代码改动 | 同步更新 |
   |---|---|
   | 新增 / 移除 <单元> 或<组> | 新建 / 删除该篇 + 更新所在组篇速览表 + 更新根导航表 |
   | <按本仓库的域拆 6–12 行,每行 → 具体篇路径> | … |

   拿不准改哪篇时,至少更新该改动所在组篇与根导航表,确保索引不失真。
5. **验证** —— 按下方「验证矩阵」跑对应命令,全绿再提交。
6. <注释/提交信息约定>

## 验证矩阵(按改动范围选跑)

| 改动范围 | 必跑命令 |
|---|---|
| 任何改动 | <fmt + lint> |

| <协议/公开面> | <门禁> |
| 文档 / 注释 | 无需跑测试,自查链接与命令是否仍有效 |

## 约定

- <强制注释语言 / 错误类型选择 / 特殊构建口径等 3–6 条>

| <单元> | 一句话职责 | 本地契约在哪 |

## 跨层边界

- <本层与上下层的契约:>方向允许什么、禁止什么、破坏了会怎样>
