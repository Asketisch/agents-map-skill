# restructure —— 按功能搬移代码(仅经显式批准的门禁阶段)

目标:让「无限细分」由**目录结构**承载,而不是由长枚举文档承载。三类提案共用本协议:

1. **重组类**——某目录直接平铺源文件 >~20(splitting.md 文件扇出)。低加权代码量、父篇提到过该目录,都不取消。把文件按功能归入子目录。
2. **分层类**——直接有实质内容的子目录 >~15(splitting.md 目录扇出)。子目录已经存在,不等于已经拆开。把这些子目录收成 2–8 个分组目录。
3. **归位类**——layout.md 位置体检发现错位文件、根目录杂物、碎目录时,把文件移到符合项目落点约定的位置。

三类都遵循同一规则:文档树镜像新结构——agent 沿目录逐层下钻,每篇 AGENTS.md 天然保持短小。把多个子项挤进路由篇的少数单元格,不算已经下钻。

## 1. 定位与前置条件

- 仅两种入口:audit 报告中的搬移提案(重组类、分层类或归位类)被用户批准后进入;或用户显式 `/agents-map restructure`。永不自动推断进入,sync 中永不出现。
- 每次运行只处理**一个信号触发的目录**(或其一批同族目录,须逐个确认)。
- 前置检查:`git status --porcelain` 必须为空——搬移要求干净工作树,失败时 revert 才不含糊。不满足则停下报告,不做部分执行。

## 2. 取证(重组类与分层类聚类,归位类单文件举证)

**重组类**:把目录内文件分成 **2–8 个**功能子目录。证据按优先级取证,每个候选分组都要能列出依据:

1. **跨树同名**:兄弟树用同一套名字对齐时(如 `contracts/chat.ts` 与 `features/chat`、`logic/chat`、`render/chat`),分组键覆盖所有这些树,写进同一份提案,避免只动一棵树把垂直切片拆散。
2. **命名前缀/后缀**聚类(`auth_*.py`、`*_handler.ts`);
3. **引用共现**:对每文件的入口符号 `git grep -l <符号> -- <目录>`,互相引用的文件成簇;
4. **测试对应**:`test_foo.py` / `foo_test.go` / `foo.test.ts` 跟随 `foo` 所在簇;
5. **git 共变**:`git log --format= --name-only --since=6.months -- <目录>`,同提交中一起出现的文件成簇;
6. 包注释 / docstring / 目录内 README 的自述分类。文档里已有的分组标题只当线索,不当权威。

规则:

- **每个被移动的文件必须在提案里带 ≥1 条正向证据**;给不出证据的文件原地不动——宁可父目录少几个平铺项,不造假分组。
- "common" / "core" 类目录仅收**被 ≥半数其他簇引用**的文件,否则并入其唯一引用者所在簇。
- 目标每簇 ≥3 个文件,避免制造立刻触发合并回退(splitting.md 反向触发)的碎目录。

**分层类**用同一份证据清单,移动的是已有子目录而不是平铺文件。每个被移动的子目录至少一条正向证据;给不出证据的留在原地。按子目录计簇,每组至少 2 个被移动的子目录,避免造出立刻触发合并回退的碎目录。用户拒绝搬移时,报告保持未收敛,不为尚不存在的分组目录建篇。

**归位类**(layout.md 信号 2/3/4)不经聚类:错位文件、根目录杂物按单文件提案(仍须 ≥1 条正向证据,目标位置从项目落点约定取);碎目录合并以引用者分析代替聚类——目标目录是唯一/主要引用者所在目录。证据、批准门与禁移清单对三类一视同仁;归位类的批处理粒度是**一个目录或一个信号批次**,不强行凑簇。

## 3. 提案格式与批准门

```
| 文件或子目录 | 目标位置 | 证据 | 风险标注 |
```

- 风险标注含:是否被目录外 import / 是否有配置文件按路径引用它(见 §6 排查)、是否属于公开 API 面。
- 提案同时给出**预期文档树 diff**(搬完后哪些层会长出新篇)。
- 输出提案后**停下,等用户逐目录批准**。批准只绑定本轮新生成的提案——skill 无跨会话状态,换会话执行时必须重新生成并再次确认。提案首次产出的同一轮内,未经用户明确同意不得执行。

## 4. 执行协议

一个簇批次 = 一个**纯 `git mv` 提交**(`refactor(<目录>): <簇名> 按功能归入 <子目录>`):

- 移动提交中**不得混入任何内容修改**——内容改动会把 diff 相似度拉到 50% 以下,丢失 git rename 追踪。import/声明修正是移动之后的独立提交。
- 每批完成后立即修正声明与引用(§5),然后跑项目的构建 + 测试命令;**失败 → `git revert` 该批的移动与修正提交,停止本次运行并报告**,不带伤继续下一批。
- 全部批次变绿后,才按 splitting.md 的 DFS 为搬移后的子树生长 AGENTS.md(§7),文档单独提交。

## 5. 语言机制

搬移后按项目实际的构建入口验证,不套固定命令。下面只列路径会怎么断、公开面怎么守:

- **声明式模块(Rust)**:`foo.rs → foo/<cluster>/mod.rs`(或 `parent.rs` + 目录,随项目 edition 惯例);更新 `mod` 声明。对外导出的符号在旧路径加 `pub use` 再导出垫片,保持公开 API 稳定,并在新 AGENTS.md 中注明垫片是临时物及移除计划。
- **路径别名(TS/JS)**:改写相对 import;检查 tsconfig / bundler 的 `paths` 与 barrel 转发文件。
- **仓内 import(Python、Ruby)**:Python 建 `__init__.py` 并改写 `from` / `import`;Ruby 改 `require` / autoload。`importlib`、`mock.patch`、entry_points、插件发现、gemspec 字符串常量等引用只报告不盲改,列入提案风险栏。
- **公开导入路径**:这次搬移会改掉已发布包路径或命名空间时,默认**只提案不执行**——§3 后即终止,用户在执行前做第二次显式确认才继续。Go 最严,因为仓外消费者本仓看不见;JVM、PHP、C# 里同样会改掉已发布导入路径的搬移适用同一条。
- **头源成对(C/C++)**:`.h` / `.hpp` 与对应 `.c` / `.cpp` 同一批搬,不拆开。
- 验证命令取自目标项目已有的 AGENTS.md 或构建文件。项目没写明命令时,提案里列出打算跑的命令并等确认。

## 6. 禁移清单

以下文件永不进入搬移提案:

- 生成代码(`*.pb.*`、codegen 目录产物)、lockfile、vendor、submodule 内容;
- DB 迁移文件(**文件名顺序即契约**);
- 构建入口 / root bin:各语言的构建入口(Cargo `[[bin]]`、`package.json` 的 main/bin、Go `cmd/*/main.go`、JVM 的 `main` 类、.NET 启动项目、C/C++ 构建系统点名的入口、Composer `bin`、gemspec executables);
- 被外部路径字符串钉住的文件:对每个候选文件 `git grep -F <文件名/路径>` 过一遍 `.github/`、`Dockerfile*`、CI 配置、systemd unit、资源加载器,命中即标"路径被外部引用"并默认排除;
- 测试与源码**同目录共存惯例**(Go `_test.go`、colocated `*.test.ts`)不属于禁移,而是**测试跟随其源码同批搬移**,永不拆散。

## 7. 文档跟随

全部批次变绿后,在本阶段内完成:

1. 对重组子树跑 splitting.md 的 DFS,新子目录按模板 B/C 建篇;
2. 更新原目录篇(现在是路由篇)的速览表与父篇导航链接;
3. 更新根篇「代码改动 → 同步更新」映射表中指向旧路径的 glob 前缀;
4. `bash scripts/check_agents_docs.sh --structure <repo>` 复查信号已消失,再跑一遍无旗标自检。

## 8. 回滚

每个簇批次的「移动提交 + 修正提交」是一个可独立 `git revert` 的单位;文档提交各自独立回滚。revert 顺序:先文档后代码。任何一批 revert 后,整次 restructure 运行终止并报告,不把剩余批次留在空中。
