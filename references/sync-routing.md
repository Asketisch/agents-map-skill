# sync 路由算法:diff → {目标篇, 目标节}

## 锚点与变更集

每篇 AGENTS.md 用 `git log -1 --format=%H -- <文档路径>` 单独取基线；收集该基线到 HEAD 的变更，并并入暂存、未暂存及未跟踪文件。使用 NUL 分隔路径，处理重命名的旧、新路径。提交中的文档修改不保证同步了全部代码，基线仅是启发式。

无提交历史、无 Git、浅克隆或历史不完整时标明限制并做完整审查；不得报告全面覆盖。排除构建产物及 submodule 内容，但报告 submodule 指针变化。逐篇列出基线和检查范围。

## 路由 = 三层信号的并集

### 信号 1:结构性(确定性,纯路径运算,不读 diff 内容)

- **成员/目录集合增删**(workspace members、`crates/*/`、顶层目录、或任意深度节点的子目录):审查相关文档及最近父篇，仅在实际需要时增删篇目或更新导航;子树规模跨 30k 加权代码量阈值的目录变更按 splitting.md 提议下拆。这是唯一同时触发多层级联的信号。
- **最近祖先 AGENTS.md**:任一变更文件向上找到的第一个 AGENTS.md,其责任范围即该文件的**默认目标篇**。
- `scripts/ tests/ sdks/ .github/ docs/` 下文件增删 → 对应目录篇速览表。
- **公开面 diff**:diff 内容命中 `^[+-].*pub (fn|struct|trait|enum)`,或入口/barrel 文件命中 `^[+-]export` / `__all__` → 所在组篇「跨层边界」,并可能牵动根篇契约描述。

### 信号 2:语义性(根篇「代码改动 → 同步更新」映射表)

把根篇映射表每行解析为 `(路径 glob 或关键词, 目标篇集合)` 做匹配。该表由 init 生成、sync 维护,是**项目本地路由器**;表缺失时算法退化为只有信号 1(见下 bootstrap)。

### 信号 3:断言比对(最贵,只对信号 1/2 命中的篇执行)

打开目标篇,提取「本地契约与同步点」「禁止事项」中加粗断言里的标识符(类型名/文件路径/命令名),逐一 `git diff "$ANCHOR"..HEAD` 查是否被动过 → 动了就标 **"断言需人审"**,报告给用户,**不自动删改**。

## 节级二次路由(命中篇后定位到节)

| diff 特征 | 目标节 |
|---|---|
| 文件增删 | 核心文件导航表 |
| 签名 / 行为变化 | 本地契约与同步点 |
| 测试用例落点规则变化 | 开发流程检查表 + 根映射表对应行 |
| 构建入口 / CI / 测试 runner 变化 | 根篇 常用命令 + 验证矩阵 |
| 其余 | 注意事项 |

## 映射表 bootstrap(有体系但根篇无映射表)

1. 每个组篇 → 一行:「`<该组目录>` 下代码变更 → 该组篇 + 其链接的成员篇」(取自根导航表与速览表现状);
2. scripts/tests/sdks 类顶层目录各一行;
3. 语义细化行**不预设**——仅在发现真实的重复漂移模式时建议补充;
4. 末尾恒有兜底行:「其它变更 → 审查最近祖先篇，必要时审查根导航」。

## 收敛检查

全部更新后**重跑一次本算法**,核对每条报告事项是否已修改、确认无需修改或仍待处理，记录理由。原始 diff 信号不会因文档编辑自动消失。

## 特殊情形

- **submodule 镜像篇**:上游文档随 submodule 带入的副本(如各下游仓库 `zhuye-agent/AGENTS.md`)永不路由;其路径出现在 diff 里只意味着指针升级。
- **映射表自身会腐烂**:「映射表行指向已删除的篇/路径」列入信号 3 检查,否则路由静默指错。
